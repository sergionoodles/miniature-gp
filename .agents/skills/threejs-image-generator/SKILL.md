# Three.js Image Generator

Provide briefs, prompts, and intake decisions without provider setup. Use supplied/licensed images or an authorized managed image tool; otherwise return a ready-to-use prompt and intended runtime use.

## Prompt patterns

- **Image-to-3D:** centered single object, complete silhouette, plain background, clear material boundaries, no blur/cropping/unwanted text.
- **Riggable subject:** complete symmetric T/A pose or suitable creature stance, separated visible limbs, no props fused to hands.
- **Texture:** seamless surface, orthographic view, lighting-friendly albedo, no strong baked shadows or unwanted perspective.
- **UI:** crisp icon/logo/badge, legible at display size, high contrast, clear silhouette, alpha when supported. Verify requested text.
- **Background:** wide composition, layered depth, readable horizon, clear gameplay area, coherent palette/lighting.

Add game-specific style, materials, camera, and use constraints. Select resolution for display size and memory budget.

## Editing and intake

Inspect the source before editing, preserve originals/usable variants, and specify changes precisely. Check alpha edges, seams, palette, readability, and dimensions before dependent 3D work. Assess images in-game when available. Recommend PNG for alpha and supported compressed formats for large opaque surfaces. Save authorized outputs in established project locations. No generation keys or calls belong in the game runtime.

## Report

Give purpose, prompt, actual source/output paths, dimensions, findings, and runtime use or 3D handoff. Label prompt-only work clearly.

## Use boundaries

This skill is written guidance. No bundled code, command execution, installation, credentials, or external service is required. Planning and review can produce recommendations from the supplied brief and artifacts. Project implementation and existing tools apply only within the user's requested work and execution permissions.

Do not source shell profiles, search for secrets, change machine configuration, execute downloaded content, or bypass permission controls. Skill invocation does not authorize paid jobs, uploads, publishing, deployment, or destructive overwrites. Use an available managed tool only when its action, data transfer, and cost are authorized. Otherwise provide a local alternative or written handoff. Stop on authentication, permission, or budget failures; reconcile uncertain submissions before any replacement.
